# Exported configuration structure

These tools create or expect a configuration repository with the structure below. Configuration consists of

- Realm specific configuration under the `realms` top level directory

- Global configuration under its respective top level directories

### Realm specific configuration

The configuration repo contains the top level directory `realms` with a subdirectory for each of the realms to be pushed/pulled - `alpha` and/or `bravo`. Each realm directory has the following subdirectories:

| Directory              | Contents                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| scripts                | This directory contains one JSON file per script defined in this realm. The scripts themselves are created under `script-content/{script-type}`.                                                                                                                                                                                                                                                                                                                                                                 |
| journeys               | This contains a subdirectory `{journey-name}` for each journey configured in the realm. Each of these subdirectories contain the file `{journey-name}.json` with the overall tree configuration, together with a `nodes` subdirectory containing one file per node in the tree. Node config filenames are formatted as `{node-display-name} - {tree-node-id}.json`. In the case of Page nodes, all child nodes are contained within a subdirectory named: `{page-node-display-name} - {page-tree-node-id}.json`. |
| password&#x2011;policy | `{realm}_user-password-policy.json` contains the realm password policy                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| services               | This directory contains one file `{service-name}.json` per access management service configured in the realm.                                                                                                                                                                                                                                                                                                                                                                                                    |
| themes                 | There is one subdirectory `{theme-name}` per theme defined in the realm. Each theme directory has the file `{theme-name}.json` containing the top level theme configuration, alongside separate HTML files containing the header and footer contents.                                                                                                                                                                                                                                                            |
| secret-mappings        | There is one file `{mapping-name}.json` per secret mapping defined in each realm. These are specifically the tenant specific mappings defined ni the customer accessible `ESV` secret store.                                                                                                                                                                                                                                                                                                                     |
| authorization          | This directory contains the Authorization Policy Engine configuration. There are two subdirectories - `policy-sets` contains a subdirectory per policy set, and `resource-types` contain the authorization resource types in use by these policy sets. This directory is populated by the `fr-config-pull` tool according to the list of policy sets defined in the `.env` file.                                                                                                                                 |
| realm-config           | This directory contains the overall configuration for each realm, such as `authentication.json`, together with the subdirectory `agents` which contains the OAuth2 agents to be exported/imported for each environment. This directory is populated by the `fr-config-pull` tool, according to the list of agents defined in the `.env` file.                                                                                                                                                                    |

## Global configuration

The configuration repository contains the following directories for tenant-wide
configuration—that is, configuration that is not specific to a realm:

| Directory          | Contents                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sync`             | Contains the following subdirectories:<br><br>`connectors` contains one JSON file per connector, named `{connector-name}.json`.<br><br>`mappings` contains one JSON file per synchronization mapping, named `{mapping-name}.json`.<br><br>`rcs` contains the remote connector server configuration in `provisioner.openicf.connectorinfoprovider.json`.                                                                                                                                                                                                                              |
| `cors`             | Contains the tenant-wide CORS configuration in `cors-config.json`, including settings for both the `/am` and `/openidm` endpoints.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `email-provider`   | Contains the external email service configuration in `external.email.json`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `email-templates`  | Contains one subdirectory, `{template-name}`, per email template. Each subdirectory contains the top-level template configuration in `{template-name}.json`, together with the following files:<br><br>CSS: `{template-name}.css`<br>HTML: `{template-name}.{lang}.html`<br>Markdown: `{template-name}.{lang}.md`                                                                                                                                                                                                                                                                    |
| `access-config`    | Contains the authorization configuration for `/openidm` endpoints in `access.json`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `endpoints`        | Contains one subdirectory per endpoint. Each subdirectory contains the endpoint configuration in `{endpoint-name}.json` and, where applicable, the endpoint JavaScript in `{endpoint-name}.js`.                                                                                                                                                                                                                                                                                                                                                                                      |
| `schedules`        | Contains one subdirectory per schedule. Each subdirectory contains the schedule configuration in `{schedule-name}.json` and, where applicable, the schedule script in `{schedule-name}.js`.                                                                                                                                                                                                                                                                                                                                                                                          |
| `kba`              | Contains the tenant-wide Knowledge-Based Authentication configuration in `selfservice.kba.json`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `managed-objects`  | Contains one subdirectory, `{object-name}`, per managed object. Each subdirectory contains the top-level managed-object configuration in `{object-name}.json`, together with one JavaScript file per event-trigger script, named `{object-name}.{event-trigger}.js`.                                                                                                                                                                                                                                                                                                                 |
| `terms-conditions` | Contains the top-level terms and conditions configuration in `terms-conditions.json`, together with one subdirectory, `{terms-version}`, per configured version. Each version subdirectory contains one `{language}.html` file per configured language.                                                                                                                                                                                                                                                                                                                              |
| `ui`               | Contains the hosted UI configuration in a JSON file.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `esvs`             | Contains the following subdirectories:<br><br>`secrets` contains one JSON file, `{secret-name}.json`, per environment secret.<br><br>`variables` contains one JSON file, `{variable-name}.json`, per environment variable.<br><br>Each JSON file contains a placeholder for the `valueBase64` value. The placeholder is intended to be replaced with an environment variable during the configuration push. Secret files can contain one or more versions; the highest version becomes active after the push. Any pre-existing secret versions are removed after the push completes. |
| `internal-roles`   | Contains one JSON file, `{role-name}.json`, per authorization role configured in the tenant. System roles, such as `openidm-admin`, are excluded because they have no configured privileges.                                                                                                                                                                                                                                                                                                                                                                                         |
| `service-objects`  | Contains managed objects to push to each environment, such as service-managed users and roles. There is one subdirectory per managed-object type. Each subdirectory contains one JSON file per object to create. Every object JSON file must contain an `_id` attribute so that the object is created or updated with a fixed ID.                                                                                                                                                                                                                                                    |
| `locales`          | Contains the UI message strings for all configured locales. There is one file, `{locale}.json`, per locale.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `audit`            | Contains the tenant-wide identity-management audit configuration in `audit.json`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `org-privileges`   | Contains the organization privileges configuration in three files: `alphaOrgPrivileges.json`, `bravoOrgPrivileges.json`, and `privilegeAssignments.json`.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `raw`              | Contains raw configuration. The `fr-config-pull raw` command creates individually pulled configuration objects in this directory, and the `fr-config-push raw` command searches this directory for configuration to push.                                                                                                                                                                                                                                                                                                                                                            |
| `custom-nodes`     | Contains one subdirectory per custom node. Each subdirectory contains the node configuration JSON and a separate file containing the node script source.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `custom-policies`  | Contains one subdirectory per custom policy. Each subdirectory contains the policy configuration JSON and a separate file containing the policy logic function.                                                                                                                                                                                                                                                                                                                                                                                                                      |
